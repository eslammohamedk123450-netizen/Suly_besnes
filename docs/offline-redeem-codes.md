# تصميم أكواد المكافآت دون اتصال

## التوصية

استخدم قسائم موقعة رقميًا بدل وضع قائمة أكواد ومكافآتها داخل ملفات اللعبة. يُنشأ كل كود خارج التطبيق بتوقيع Ed25519. يحتفظ المالك بالمفتاح الخاص في أداة إصدار منفصلة ومحمية، ولا يُضمّن هذا المفتاح في APK أو مستودع GitHub. يضم التطبيق المفتاح العام فقط، فيتحقق من أن القسيمة صادرة عنك ولم يُعدّل أحد محتواها، حتى عندما لا يوجد اتصال بالإنترنت.

## شكل القسيمة

تحمل القسيمة نسخة الصيغة، معرفًا فريدًا، تاريخ الإصدار والانتهاء، وقائمة مكافآت typed، ثم التوقيع على كامل الحمولة. يمكن تحويل الحمولة والتوقيع إلى Base64URL ونشرهما كسلسلة قابلة للنسخ، مثل:

```text
SULY1.<payload-base64url>.<signature-base64url>
```

من أمثلة عناصر المكافآت التي يمكن جمعها في كود واحد:

```json
{
  "version": 1,
  "codeId": "unique-id",
  "expiresAt": "2027-12-31T23:59:59Z",
  "rewards": [
    { "type": "cash", "amount": 50000 },
    { "type": "material", "materialId": "steel", "quantity": 5 },
    { "type": "gold", "grams": 0.5 }
  ]
}
```

الحقول هنا توضيحية: التنفيذ الفعلي يجب أن يتحقق من قائمة أنواع مسموحة وحدود عليا لكل مكافأة، ومن العملة والدولة والنسخة، ويرفض أي حقل مجهول أو كمية غير صحيحة. لا تقبل اللعبة مكافآت مجانية بأرقام عشوائية من النص المدخل.

## مسار الإصدار والاسترداد

1. تشغّل أداة إصدار خارج اللعبة، تختار نوع المكافأة أو حزمة تجمع رصيدًا وأرضًا ومواد وتوسعة مصنع، ثم تولّد `codeId` عشوائيًا ووقت انتهاء.
2. توقّع الأداة الحمولة بالمفتاح الخاص، وتُخرج نص الكود. يستطيع المالك نسخ الكود وإرساله للشخص.
3. يدخل اللاعب الكود في شاشة الاسترداد. تتحقق اللعبة من الصيغة والتوقيع والصلاحية والحدود وأن `codeId` غير موجود في سجل أكواده المستردة.
4. تطبق اللعبة جميع المكافآت كمعاملة واحدة: إما تُطبّق كلها وتُسجل في الدفتر المحلي، أو لا يتغير أي شيء. تحفظ `codeId` مع ملف اللاعب كي لا يُسترد مرتين في ملف الحفظ نفسه.
5. تعرض اللعبة إشعارًا أعلى الشاشة يوضح المكافأة أو سبب الرفض.

قبل إصدار مكافأة عمال، أضف نظام عمال فعليًا (التوظيف والأجور وتأثير العمال على التشغيل)؛ أما قبل ذلك فيمكن للكود تخزين «قسيمة عمال» غير قابلة للاسترداد إلى حين تنفيذ ذلك النظام، لكن الأفضل عدم طرح نوع مكافأة غير مستخدم.

## حدّ offline المهم

التوقيع يمنع تزوير المكافأة أو تغيير قيمتها، لكنه لا يستطيع معرفة ما إذا كان الكود قد استُخدم على هاتف آخر لا يتصل بالإنترنت. لذلك فإن سجل الاسترداد المحلي يمنع التكرار على ملف الحفظ/الجهاز نفسه فقط؛ يمكن نسخ الكود إلى أجهزة أخرى أو حذف بيانات التطبيق ثم استرداده مجددًا.

إذا كانت الأكواد عامة ومتعددة الاستخدام، فهذا مناسب ويمكن تحديد عدد الاستخدامات بكمية الأكواد التي تصدرها، أو جعلها صالحة حتى تاريخ معين. أما إذا كان مطلوبًا أن يعمل الكود مرة واحدة عالميًا فقط، فلا يمكن ضمان ذلك بالكامل أثناء بقاء الهاتف offline. الحل الهجين هو التحقق من الكود مرة واحدة عبر الإنترنت عند الاسترداد، وتسجيل استخدامه مركزيًا؛ بعد ذلك يبقى اللعب والتقدم دون اتصال. لا يحتاج اللعب إلى خادم، لكن الاسترداد العالمي يحتاج اتصالًا لحظيًا.

## تقسيم الملفات المقترح عند التنفيذ

- `src/domain/rewards.ts`: أنواع المكافآت والحدود المقبولة.
- `src/game/redeemCode.ts`: فك الحمولة والتحقق من التوقيع والصلاحية وعدم تكرار المعرف، ثم إنتاج نتيجة المعاملة.
- `src/storage/saveRepository.ts`: رفع مخطط الحفظ وإضافة سجل `redeemedCodeIds` مع ترحيل محافظ.
- `src/components/CodeRedemption.tsx`: حقل إدخال الكود ورسائل الخطأ والنجاح.
- `tools/issue-code.mjs`: أداة إصدار تعمل محليًا خارج APK وتقرأ المفتاح الخاص من ملف محلي غير متعقب.
- مفتاح التحقق العام فقط: ثابت في التطبيق. المفتاح الخاص ونسخه الاحتياطية تبقى خارج GitHub وملفات البناء.

## القرار المطلوب قبل التنفيذ

بما أن شرط العمل دون اتصال لا ينسجم مع ضمان «مرة واحدة عالميًا»، فالتوصية لهذا المشروع هي إصدار أكواد موقعة تعمل بالكامل offline وتُمنع مرة واحدة لكل ملف حفظ محلي. إذا كان الاستخدام العالمي لمرة واحدة أهم من العمل دون اتصال أثناء الاسترداد، فيلزم اختيار المسار الهجين والتحقق عبر الإنترنت عند الاسترداد فقط.
