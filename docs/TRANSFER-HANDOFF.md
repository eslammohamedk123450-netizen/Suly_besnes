# ملف تسليم مشروع إمبراطورية الأعمال

هذا الملف مخصص لنقل متابعة تطوير المشروع إلى حساب Manus آخر دون فقدان الكود أو إعدادات الحساب السحابي.

## 1. مستودع GitHub

- المستودع: `https://github.com/eslammohamedk123450-netizen/Suly_besnes`
- الفرع الأساسي: `main`
- آخر Commit وقت إعداد هذا الملف: `81883f7 feat: connect cloud auth and synced game saves`
- حالة المستودع: نظيف ومتزامن مع `origin/main`.

الحساب الآخر يجب أن يتصل بنفس حساب GitHub الذي يملك المستودع، أو تتم دعوته إلى المستودع من إعدادات GitHub. بعد ذلك يمكنه فتح المستودع ومتابعة التطوير مباشرة.

## 2. تشغيل المشروع

من داخل نسخة المستودع:

```bash
pnpm install
pnpm typecheck
pnpm build
```

المشروع تطبيق React/Vite مع Capacitor. لا يتم إنشاء APK إلا بعد اختبار الحساب السحابي والمزامنة.

## 3. Supabase المرتبط بالمشروع

المشروع السحابي الحالي:

- Project ref: `kamxjsddjxowodatafqo`
- Project URL: `https://kamxjsddjxowodatafqo.supabase.co`
- نوع الحساب: Supabase Auth بالبريد وكلمة المرور.
- تأكيد البريد: معطل حتى يتم الدخول مباشرة بدون كود تحقق.
- جدول الحفظ: `public.game_profiles`.
- سياسات RLS: كل مستخدم يستطيع قراءة وتعديل صفه فقط.

ملف SQL المستخدم لإنشاء الجدول والسياسات موجود هنا:

```text
docs/supabase-schema.sql
```

إذا استُخدم نفس مشروع Supabase، فبيانات اللاعبين الحالية تبقى موجودة ولا تحتاج إلى نقل. يجب فقط أن يدخل الحساب الآخر إلى نفس مشروع Supabase أو تتم دعوته كعضو في مشروع Supabase.

إذا أُنشئ مشروع Supabase جديد، فلن تنتقل حسابات اللاعبين تلقائيًا. يلزم تصدير قاعدة البيانات والحسابات من المشروع القديم ثم استيرادها في المشروع الجديد، وهذه عملية منفصلة لا ينفذها GitHub وحده.

## 4. مفاتيح Supabase

التطبيق يستخدم مفتاح Supabase العام فقط، وهو موجود في `src/storage/supabaseClient.ts` كقيمة عامة مناسبة لتطبيق الويب والموبايل. لا يوجد مفتاح `service_role` أو `secret` داخل المستودع.

لا يجوز وضع أي مفتاح سري في GitHub أو داخل APK.

## 5. نظام الأكواد

مولد الأكواد موجود في:

```text
tools/issue-code.mjs
```

واستخدامه:

```bash
pnpm code:issue -- --cash 50000 --gold 0.5 --expires 2027-12-31T23:59:59Z
```

واجهة الاسترداد موجودة داخل إعدادات اللعبة. الكود يتحقق من التوقيع والصلاحية ويمنع استخدام نفس `codeId` مرتين على الحساب.

### تحذير مفتاح الأكواد

المفتاح الخاص الذي يصدر الأكواد لا يتم رفعه إلى GitHub عمدًا. يجب نقل ملف المفتاح الخاص بشكل آمن إلى الحساب أو الجهاز الجديد إذا كان مطلوبًا إصدار أكواد جديدة بنفس المفتاح.

لا ترسل المفتاح الخاص داخل المحادثة ولا تضعه في المستودع. إذا فُقد المفتاح الخاص، يجب إنشاء زوج مفاتيح جديد وتحديث المفتاح العام داخل التطبيق؛ الأكواد القديمة الموقعة بالمفتاح السابق لن تكون قابلة للإصدار من جديد.

## 6. الملفات المهمة

- `src/storage/supabaseClient.ts`: رابط Supabase والمفتاح العام.
- `src/storage/authRepository.ts`: التسجيل وتسجيل الدخول والخروج.
- `src/storage/remoteSaveRepository.ts`: تحميل وحفظ ملف اللاعب سحابيًا.
- `docs/supabase-schema.sql`: إنشاء جدول الحفظ وسياسات الحماية.
- `docs/accounts-and-codes.md`: شرح الحسابات والأكواد.
- `TODO.md`: قائمة التطوير المتبقي.
- `plan.md`: خطة المشروع وقرارات التصميم.

## 7. خطوات الحساب الآخر

1. الاتصال بحساب GitHub الذي يملك المستودع.
2. فتح مستودع `Suly_besnes` من الفرع `main`.
3. قراءة هذا الملف وملف `README.md`.
4. عدم إنشاء مشروع Supabase جديد إذا كان المطلوب استمرار بيانات اللاعبين الحالية.
5. التأكد من أن الحساب يملك صلاحية الوصول إلى مشروع Supabase الحالي.
6. تشغيل `pnpm install` ثم `pnpm typecheck` و`pnpm build`.
7. متابعة التطوير من نفس المستودع، مع عمل Commit وPush بعد كل دفعة.

## 8. ما لا ينتقل عبر GitHub

GitHub ينقل الكود والوثائق فقط. لا ينقل تلقائيًا:

- جلسة دخول Supabase.
- كلمات مرور اللاعبين.
- بيانات اللاعبين من قاعدة Supabase.
- مفتاح إصدار الأكواد الخاص.
- إعدادات لوحة Supabase غير الموجودة في ملفات المشروع.

لذلك أفضل طريقة هي استخدام نفس مستودع GitHub ونفس مشروع Supabase، ثم منح حساب Manus الآخر صلاحية الوصول إليهما.
