## 2. وصف المشروع

لعبة محاكاة أعمال عربية RTL مبنية بـ React وTypeScript وVite وCapacitor، وتستهدف الويب وAndroid. أنظمة المال والسوق داخل اللعبة محاكاة؛ لا تُعاملها كخدمة مالية حقيقية. ابدأ من المستودع القائم ولا تنشئ تطبيقًا أو قاعدة جديدة.

## 3. ما هو موجود ومُنجز في النسخة الحالية

### اللعب والاقتصاد

- حلقة تأسيس وتوسّع تشمل الأراضي والشركات والقطاعات والتراخيص والمواد الخام والمخازن وأوامر الإنتاج المؤجلة وبيع المنتجات.
- سوق مدخلات عالمي قائم على عروض شراء المواد الخام من بائعين داخل اللعبة. هذا ليس بعد سوقًا عامًا بين لاعبين لتبادل الأصول أو البضائع.
- مزادات محلية ضد منافسين آليين خياليين، لا مزادًا حيًا بين المستخدمين.
- عروض عقود ومهام يومية، مع سمعة وإنجازات وتفاوض، وشروط جودة متفاوتة. عروض الجودة والجملة والعاجلة تستخدم حاليًا حدود جودة مميزة.
- المبيعات والعقود تسجل الإيراد والضريبة وتكلفة البضاعة في دفتر اللعبة؛ تقارير الربحية تميز تكلفة البضاعة المباعة عن إجمالي أوامر الإنتاج. بيانات البيع القديمة التي ينقصها حقل تكلفة تستخدم تقديرًا رجعيًا في المحددات.
- مرور يوم محاكى ومواعيد للعقود، وأحداث وموسم ومكافآت وتحديات وترتيب عالمي/محلي بحسب المسار الخادمي.
- استثمارات وذهب محاكيان، بنك وودائع وقروض، موظفون ورواتب والتزامات وتشغيل وصيانة وتطوير شركات ومخازن.

### الدخول والحفظ والخدمات

- يدعم المشروع اللعب كضيف والحفظ المحلي، وتسجيل الحساب والدخول واستعادة كلمة المرور بحسب الواجهات الحالية. يستطيع اللاعب ربط حفظ الضيف بالحساب وفق السلوك الموجود في نسخة المشروع؛ تحقّق من طريقة الدمج قبل أي تغيير كي لا يُستبدل حفظ محلي أو سحابي بصمت.
- توجد طوابير محلية للأوامر الأولية وأوامر اللعبة ومخزن أوامر معلقة، إلى جانب وظائف Supabase خادمية تشمل `game-command` و`game-save` و`game-transaction` و`reward-code` و`season-event` و`finalize-seasons`. وجود الشفرة في المستودع لا يثبت وحده أن كل وظيفة منشورة أو سليمة حاليًا؛ تحقّق من لوحة Supabase قبل تغييرات إنتاجية.
- توجد لوحة إدارة في `src/AdminApp.tsx` ومكونات/وظائف خلفية. إصدار أكواد المكافآت من واجهة الإدارة الجديدة موثق بأنه غير مكتمل؛ لا تنقل المفتاح الخاص إلى العميل أو GitHub.
- يوجد إعداد Capacitor للموبايل. لم يُبنَ APK جديد أثناء آخر دفعة؛ لا تبنِ أو تنشر APK إلا بطلب المستخدم، ولا تعتبر أي ملف APK قديمًا مطابقًا لآخر كود.

## 5. نتيجة التحقق وآخر الفحوص

عند إعداد الملف:

- `pnpm typecheck`: ناجح.
- `pnpm build`: ناجح. يوجد تحذير غير مانع من Vite لأن حزمة JavaScript الرئيسية تتجاوز 500KB بعد التصغير؛ يمكن بحث تقسيم الحزم لاحقًا.
- `pnpm vitest run src/game src/storage`: نجح **16 ملف اختبار و73 اختبارًا**.
- شُغّل `pnpm test` كاملًا: مرّ **17 ملفًا و90 اختبارًا**، لكن تعذّر تحميل مجموعتي اختبار لوحة الإدارة `admin-dashboard/server/auth.logout.test.ts` و`admin-dashboard/server/platform.test.ts` لعدم حل الاستيراد `@shared/const`. أصلح إعداد alias/اختبارات لوحة الإدارة ثم أعد تشغيل الاختبار الكامل؛ لا تنسب هذا الفشل إلى إصلاحات الاقتصاد دون دليل.
- `git diff --check`: ناجح قبل الالتزام؛ آخر حالة دُفعت كانت نظيفة.

## 6. الأعمال المفتوحة والأولويات

راجع `TODO.md` وكود `main` معًا. توجد بنود قديمة أصبحت حالتها متقادمة بعد التحديثات الحديثة؛ لا تعتمد علامة `[ ]` وحدها دليلًا على غياب الميزة.

1. **إكمال إصدار أكواد المكافآت في لوحة الإدارة الجديدة.** نفّذ الإصدار على خادم موثوق فقط، وتحقق من شروط الصلاحية وحد الاستخدام والتوقيع ومنع إعادة الاستخدام الذري. أبقِ مفتاح التوقيع الخاص خارج الواجهة وAPK وGitHub.
2. **تحديد نطاق السوق العالمي المتبقي.** يوجد سوق عروض لشراء مدخلات الإنتاج؛ أما سوق لاعب-إلى-لاعب للبيع والشراء والتسوية الذرية فمذكور في `TODO.md` كعمل غير مكتمل. لا تُظهر صفقة أو رصيدًا عالميًا ناجحًا قبل تأكيد الخادم.
3. **إكمال التزامن عند الانقطاع والتعارض.** توجد طوابير محلية واختبارات لها، لكن يجب فحص تجربة المنتج كاملة عند انقطاع Supabase: حالة الحفظ للمستخدم، إعادة المحاولة، منع تكرار الأمر، وتسوية تعارض نسخة اللاعب عند عودة الاتصال. لا تستبدل تقدمًا أحدث بصمت.
4. **إصلاح الاختبارات الكاملة للوحة الإدارة.** اكتشف alias `@shared/const` في إعداد Vitest/TypeScript الخاص بالمشروع وحدّث الاختبارات أو الإعداد دون إضعاف الاستيرادات في الإنتاج.
5. **مراجعة أمنية خادمية وفق توثيق الأمان.** راجع `docs/BUSINESS_EMPIRE_HANDOFF_AR.md` وملفات migrations/functions قبل التنفيذ. تحقق من validator الحالة الخادمية، حدود المعدل، سجل التدقيق، CORS، وتغطية اختبارات التلاعب والتكرار والتزامن. لا تدّعِ أن وظيفة منشورة قبل فحص لوحة Supabase.
6. **تسوية الوثائق المتعارضة.** `README.md` يصف استعادة كلمة المرور، بينما أجزاء من `TODO.md` ما زالت تضعها ضمن غير المكتمل؛ الكود الحالي يحتوي مسار `PASSWORD_RECOVERY` واختبارات مصادقة. بعد مراجعة التنفيذ، حدّث علامة TODO والوصف المتقادم. وبالمثل راجع كل بند التزامن غير المتصل مقابل `src/storage/commandOutbox.ts` والاختبارات.
7. **حجم الواجهة.** تحذير الحزمة الأكبر من 500KB غير مانع، لكنه فرصة لتقسيم شيفرة لوحة الإدارة والصفحات غير المستخدمة عند الحاجة، بعد قياس أثره.
8. **التحقق المرئي والإصدار.** بعد تغييرات الواجهة، اختبر RTL والهاتف وتدفقات اللعبة عبر المعاينة. ابنِ APK فقط بتوجيه صريح، ثم وضّح رقم البناء ومصدر الملف.

## 8. أوامر البدء المقترحة

```bash
git fetch origin
git status --short --branch
git log -8 --oneline
pnpm install
pnpm typecheck
pnpm build
pnpm vitest run src/game src/storage
```

بعد ذلك جرّب الاختبار الشامل:

```bash
pnpm test
```

وتوقع حاليًا مشكلة alias لوحة الإدارة الموصوفة أعلاه إلى أن تُصلح. قبل كل تعديل، افحص `git status` وادمج تحديثات `origin/main` بطريقة غير مدمرة. بعد كل دفعة: اختبارات مناسبة، `typecheck`، `build`، `git diff --check`، ثم commit وpush. لا تستخدم force push.

## 9. قواعد الاستمرار

- لا تنشئ مستودع GitHub أو مشروع Supabase جديدًا بدل الحالي.
- لا تضع كلمات مرور أو رموز جلسات أو مفاتيح سرية في الملفات أو المحادثة.
- حافظ على توافق الحفظ القديم، وعلى الدفتر والقيود الخادمية.
- اجعل كل قرار مالي مهم يمر بمنطق موثوق، وكل أمر قابل للتكرار محميًا بمفتاح idempotency مناسب.
- لا تدّعِ مزادًا أو سوقًا حيًا بين اللاعبين إذا كان المتاح محاكاة محلية أو عروضًا خادمية للبضائع فقط.
- لا تنفّذ تغييرات قاعدة بيانات إنتاجية ولا تنشر APK دون تفويض المستخدم.
