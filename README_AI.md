# وحدة التطوير بالذكاء الاصطناعي

يحتوي المشروع على `AI Dev Console` عائمة داخل اللعبة لمساعدة المطوّر في اقتراح تعديل على **ملف واحد فقط في كل مرة**، ثم مراجعة الشرح والكود قبل حفظه محليًا.

## إعداد Ollama

1. افتح [Ollama API Keys](https://ollama.com/settings/keys) وسجّل الدخول.
2. أنشئ API key جديدًا وانسخه.
3. انسخ `.env.example` إلى `.env`:

   ```bash
   cp .env.example .env
   ```

4. ضع المفتاح في `.env` داخل `OLLAMA_API_KEY`:

   ```dotenv
   OLLAMA_API_KEY=your_key_here
   ```

### بوابة الإدخال الآمنة

بدل لصق المفتاح في واجهة اللعبة أو داخل المحادثة، استخدم بوابة الطرفية المخفية:

```bash
npm run ollama:setup
```

سيطلب السكربت المفتاح دون إظهاره أثناء الكتابة، ولن يطبعه في السجل. يُحفظ المفتاح في `.env` بصلاحية ملفات `600`، و`.env` مستثنى صراحةً من Git. بعد ذلك أعد تشغيل:

```bash
npm run dev
```

لتفعيل المفتاح. لا ترفع `.env` أبدًا إلى GitHub، ولا تستخدم `--debug` أو أوامر تطبع متغيرات البيئة.

5. أعد تشغيل خادم Vite بعد أي تغيير في `.env`.

> الأمان: لا نستخدم `VITE_OLLAMA_API_KEY`. أي متغير يبدأ بـ `VITE_` يتم تضمينه في bundle المتصفح ويمكن لأي لاعب استخراجه. كذلك لا يمكن للمتصفح استدعاء `https://ollama.com/api/chat` مباشرة لأن Ollama لا يرسل CORS headers. لذلك تمر الطلبات عبر proxy الخادم المحلي في `vite.config.ts`، ويبقى المفتاح خارج الكود العام.

> ملاحظة الموديل: `qwen2.5-coder:7b` موديل Ollama محلي، وليس موديلًا مستضافًا على Ollama Cloud. الكونسول يرسل الاسم المطلوب كما هو؛ لاستخدام Ollama Cloud اختر موديلًا ظاهرًا في [قائمة Cloud](https://ollama.com/search?c=cloud) عبر `OLLAMA_MODEL`. للاستخدام المحلي شغّل Ollama محليًا واضبط `OLLAMA_API_BASE` على عنوانه.

## استخدام الكونسول

1. شغّل اللعبة:

   ```bash
   npm run dev
   ```

2. اضغط زر **طور بالذكاء الاصطناعي** أسفل يمين الشاشة.
3. اكتب طلب التطوير بالعربية، مع وصف السلوك المطلوب.
4. اضغط **طور 🚀** وانتظر الرد.
5. راجع الملف المقترح، الشرح، ومعاينة الفرق بين الكود القديم والجديد.
6. اضغط **تطبيق** لحفظ الكود الجديد في `localStorage`، أو **إلغاء** لرفضه.

## ملاحظات مهمة

- الكونسول لا يستخدم `eval` أو تنفيذ كود عائد من النموذج.
- لا يُسمح بتطبيق اقتراح إلا على ملف موجود داخل `src`، ويجب أن يكون ملفًا واحدًا.
- تطبيق المتصفح يحفظ الاقتراح في `suly-ai-file:<path>` ويمرر حدث `suly-ai-dev-applied` لإتاحة hot reload مخصص في بيئة التطوير.
- `localStorage` ليس بديلًا عن Git. راجع الكود واختبره ثم احفظ التغيير في Git يدويًا.
- في بيئة إنتاج حقيقية، يجب نقل تطبيق التعديل إلى API مصادق عليه على الخادم؛ لا تمنح الواجهة صلاحية كتابة ملفات المشروع مباشرة.
